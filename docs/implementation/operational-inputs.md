These inputs configure the build; they do not reopen confirmed product decisions. The product requirements contain the canonical OPS register. Implement and test with explicit synthetic defaults, then replace them through authorised configuration before the affected live feature is enabled.

## Handling a blocked integration

Record the missing input, responsible person, affected acceptance IDs and safe disabled state. Complete independent work. Do not invent credentials, guess contact identities, fabricate provider success, or make live calls to customers as a test.

## Defaults

Keep them centralised and confirm real financial settings before live invoice issue. Default advance policy must never bypass the confirmed received-advance gate.
