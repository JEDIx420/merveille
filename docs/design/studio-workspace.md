## Portfolio and control polish — accepted 28 November 2026

Projects defaults to an architectural-stage Board, with locally remembered List/Cards alternatives. All six canonical stages stay visible, including empty lanes. Stage placement is read-only: managers follow Review stage to the existing guarded progression workflow. Project cards expose stage and operational status separately, with bounded identity/title, a pinned favorite, manager and explicitly styled task progress. Retain unknown historical stages rather than hiding their projects.

Search, Filters and segmented views share compact geometry. Native keyboard-select behavior remains, with consistently padded custom chevrons. Radix popovers hold filters, density and saved views, restoring trigger focus on Escape. Correct checkbox flex sizing; mobile task entry receives its own row. Group/Sort stay visible; density moves into View options. The same shared task controls serve Home and project Tasks; retained specialist selects use the common chevron treatment.

Automations is visible in primary internal navigation and authorized project tabs. `/automations` chooses private routines or currently permitted, non-archived project scopes using existing server policy predicates and APIs. Clients/consultants gain no rule access. Live execution and optional Gemini retain their actual activation gates; no migration, inference activation, jobs deployment or production promotion is included.

Use fictional populated boards, long titles, zero/one/many projects, two themes, responsive layouts, keyboard focus and 200% CSS zoom to evaluate the actual rendered result. Passing functional checks alone does not establish team acceptance of visual polish.
